# 11-宿舍超算 (DormGrid)

局域网志愿计算网格：宿舍/实验室里闲着的电脑，用一条命令组成一台"临时超算"。
协调器切分任务、工作节点自动领活，结果自动汇总。内置第一个负载：**Mandelbrot 分布式渲染**（用于验证全链路）。

三种形态：CLI（本目录）、Web 仪表盘（协调器自带）、**桌面端**（`desktop/`，角色管理二合一）。
核心零依赖：只要机器上有 Node（≥18），把文件夹拷过去就能入网；工作节点还能打包成
**免装 Node 的单文件 exe**（见下文"单文件 exe"），拷一个文件就能加入网格。

## 桌面端（推荐入口）

Electron 应用，一个窗口管理两种角色，**全流程图形界面**（含 Blender 农场）：

- **协调器**：选任务类型（演示渲染 / Blender 农场）+ 填端口一键启动，状态徽标实时显示，一键打开内嵌仪表盘窗口。
- **Blender 工程**：农场模式下在界面里选 .blend 文件、填帧范围即可提交，无需命令行。
- **工作节点**：填名称加入网格（留空地址 = UDP 广播自动发现），实时看自己的领活/交卷日志。
- **一键全开**：协调器 + 本机节点 + 仪表盘，一步到位（演示模式）。
- 端口/任务类型/节点名/性能模式自动记忆；"输出目录"按钮直达成图与 mp4。
- 日志分级：普通事件弱化、里程碑（就绪/上线/进度/组图/收工）高亮、错误红显，可一键"只看重要"；
  内核侧同步降噪（逐瓦片日志合并为四分位进度，空闲/让路提醒降频，秒级小任务不刷屏）。

```bash
cd desktop
npm install                      # 国内网络慢时: ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js
npm start                        # 打开桌面端
npm run e2e                      # 无人值守验证: 自动起协调器+2节点全新渲染, 截图并写 e2e-result.json 后退出
```

桌面端以子进程方式运行内核（`ELECTRON_RUN_AS_NODE`），应用崩溃不影响网格，关闭窗口自动清理全部子进程。

### 打包便携版（发给其他电脑）

```bash

```

单个 exe 文件，**拷到任何 Windows 电脑双击即用**：不需要 Node、不需要安装、不写注册表。
内核（协调器/工作节点逻辑）随包携带，界面与开发版完全一致。数据落点：

- 网格数据（瓦片/成图/上传的工程）：`%APPDATA%\DormGrid\grid\`，界面上的"输出目录"按钮一键直达。

打包产物自身可用 E2E 验证：`DormGrid-0.1.0-portable.exe --e2e` 会无人值守跑完真实渲染并写
`%TEMP%\dormgrid-e2e\e2e-result.json` 后退出（exit 0 = 通过）。

## 架构

```
[协调器 coordinator]  一台常驻机器
   任务切分 · 派发 · 回收 · 瓦片落盘(断点续算) · 自动组图 · Web 仪表盘
        ↑ UDP 广播自动发现（端口 47823）         ↓ HTTP API（端口 47820）
   ┌──────────┬──────────┐
[节点 node-1] [节点 node-2] [节点 node-3 ...]
   领任务 → 多线程渲染 → 交卷，循环，直到整图完成
```

- 任务切分为"瓦片"（默认 2560×1440 切 8×4 = 32 块），天然负载均衡。
- 工作节点可以随时加入/退出；超过 15 分钟没交卷的任务会自动重新排队。
- 全部瓦片到齐后自动拼装成图，并生成预览图。

## 快速开始

### 单机演示（1 个协调器 + 2 个节点）

```bash
node dormgrid.js serve &
node dormgrid.js work -coordinator 127.0.0.1:47820 -name node-1 &
node dormgrid.js work -coordinator 127.0.0.1:47820 -name node-2 &
# 浏览器打开 http://127.0.0.1:47820 看进度与成图
```

或直接运行 `scripts/demo.sh` / 双击 `启动协调器.bat` + `加入集群.bat`。

实测数据（本机双节点，32 线程）：node-1 完成 17 块 / 3.1s，node-2 完成 15 块 / 3.5s，
全图约 3.5 秒完成组装。

### 真·两台机器

1. A 机（接仪表盘/出图的那台）：`node dormgrid.js serve`
   控制台会打印所有局域网地址，如 `192.168.17.1:47820`。
2. 防火墙放行 TCP `47820` 和 UDP `47823`（或临时关闭防火墙）。
3. B 机：把整个文件夹拷过去，然后
   - 自动发现（同一网段即可）：`node dormgrid.js work -name node-2`
   - 或直连：`node dormgrid.js work -coordinator A机IP:47820 -name node-2`
4. 所有节点收工后，A 机 `output/mandelbrot.png` 即整图。

## 命令与参数

| 命令 | 参数 | 说明 |
|---|---|---|
| `serve` | `-port 47820` | HTTP 服务端口 |
| | `-addr 0.0.0.0` | 监听地址（仅本机用 `127.0.0.1`） |
| | `-dir .` | 数据目录（`tiles/` 与 `output/` 的父目录） |
| `work` | `-coordinator host:port` | 协调器地址，省略则 UDP 广播自动发现 |
| | `-name 节点名` | 仪表盘上显示的名字，默认主机名 |
| | `-threads N` | 渲染线程数；默认（克制模式）取核心数一半，`0` = 全部 |
| | `-no-polite` | 关闭空闲让路（即"全力"模式） |

## 性能与礼貌模式

| 模式 | 行为 | 适合 |
|---|---|---|
| **克制**（默认） | 只用一半线程；检测到键鼠活动（2 分钟内）或电池供电时暂停领新任务 | 日常挂着蹭算力，不影响主人用电脑 |
| **全力**（`-threads 0 -no-polite`） | 全部线程，不让路 | 专机/挂机过夜渲染 |

- 让路只作用于"领新任务"：正在算的一块瓦片会算完再让（单块秒级，无需打断）。
- 探测不可用（非 Windows、PowerShell 受限）时自动放行（fail-open），绝不因为探测失败而罢工。
- 桌面端工作节点卡片里有"性能模式"下拉框，无需记参数。

## Blender 渲染农场

把动画渲染分给全网格：一帧 = 一个任务，帧与帧独立并行。

**桌面端全图形界面路径（推荐）**：主机任务类型选「Blender 农场」启动协调器 → 副机桌面端"加入网格" →
主机在「Blender 工程」卡片选 .blend 文件、填帧范围、点"提交渲染"。全程无命令行。

命令行等价写法：

```bash
# 机器A（出片的那台）:
node dormgrid.js serve -job blender

# 其他机器（需装 Blender；portable 版用 -blender 指路径即可）:
node dormgrid.js work -coordinator A机IP:47820

# 任意机器提交工程:
node dormgrid.js submit blender -blend scene.blend -frames 1-120 [-fps 24]
```

- `.blend` 工程按内容哈希分发，每台节点只下载一次并校验 sha256。
- 没装 Blender 的节点自动领不到帧任务（能力匹配）；渲染线程跟随性能模式。
- 完成后协调器 `output/frames/` 出帧序列 + `manifest.json`；装了 ffmpeg 会自动合成 `movie.mp4`。
- 实践要点：工程用 Blender 的 pack all 内嵌贴图（否则节点渲出粉红块）；引擎选 Cycles（CPU 无头渲染最稳）。
- 没装 Blender 也能体验全链路：`tools/fake-blender.js` 模拟 blender 接口，测试套件用它做端到端验证。

## 单文件 exe（免装 Node）

```bash
bash scripts/build-exe.sh        # 产物: dist/dormgrid.exe（约 89MB，内含 Node 运行时）
```

把 `dormgrid.exe` 单独拷到任何 Windows 机器（无需装 Node）：

```
dormgrid.exe serve -port 47820            # 当协调器
dormgrid.exe work -coordinator IP:47820   # 当工作节点（默认克制模式）
```

**双击 exe（不带参数）会进入交互菜单**：选 1 当协调器、选 2 加入集群（直接回车 = 当协调器）。
出错或收工时窗口会停留等待回车，方便看清原因，不会一闪而过。
脚本/测试里可用 `DORMGRID_MENU=1` 强制走菜单（管道输入下行为与 TTY 一致）。

首次运行如遇 SmartScreen 提示：点"更多信息 → 仍要运行"（自打包 exe 无签名）。

## HTTP / UDP 协议

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/register` | POST | `{name, cores, exes}` → `{worker_id}`；exes 为节点能力（如 `["blender"]`） |
| `/api/task?worker=id` | GET | 领一个任务（瓦片 JSON 或 exec 命令模板），无任务/无能力返回 204 |
| `/api/result/{id}?worker=id` | POST | 交回结果（瓦片 = RGBA 定长字节；exec = 输出文件字节） |
| `/api/fail/{id}?worker=id&reason=` | POST | 上报任务失败，重新排队 |
| `/api/job/blender?frames=1-240&fps=24` | POST | 提交 .blend 工程（请求体 = 文件字节） |
| `/api/asset/{sha256}` | GET | 下载任务资产（工程文件等） |
| `/api/status` | GET | 进度 / 节点 / 任务状态（仪表盘在用） |
| `/` `/image.png` `/tiles/*` | GET | 仪表盘 / 成图 / 瓦片图 |
| UDP `47823` | — | 广播 `DORMGRID_DISCOVER_V1` → 应答 `DORMGRID_HERE_V1 <端口>` |

## 目录产物

- `tiles/tile_xx_yy.png` + `.raw` —— 每块瓦片的 PNG（仪表盘展示）与 RGBA 原始数据（组装用）。
  协调器重启时，磁盘上已有的 `.raw` 自动续用，不必重算。
- `output/mandelbrot.png` —— 2560×1440 成图；`output/preview.png` —— 640 宽预览。

## 已知限制与信任边界

- **无认证无加密**：任何能连上协调器端口的人都能注册领任务。更要注意的是：**exec 负载（Blender 农场等）意味着协调器可以在工作节点上执行命令**——blender 渲染本质是运行协调器下发的指令模板。因此只该在彼此信任的机器之间组网（宿舍/实验室），绝不接陌生网络。
- 工作节点下载的资产按 sha256 校验，文件名做路径穿越过滤；任务失败有熔断与毒丸上限，不会无限重试空转。
- 节点被强杀（进程级）时，在跑的渲染子进程会被登记清理（`process.on('exit')`）；桌面端停止节点使用 `taskkill /T` 整树击杀。仅当宿主进程被 Windows 强制终止且无清理机会时才可能残留孤儿进程。
- 节点表按"注册过"统计，节点退出后仍显示在列表中（心跳过期标灰待做）。
- 负载：Mandelbrot（内置）与 Blender 帧农场；转码/OCR 等命令行负载待模板化。CPU 渲染，尚未用上 GPU。

## 已修复的 bug（验证套件抓出或代码复查发现）

1. **重启不组图**：上次运行瓦片已齐全但组图前进程被杀，重启后 complete 永远不为真，节点空转。修复：启动时/状态查询时检测瓦片齐全即自动组图。
2. **UDP 公告端口错误**：announce 的是请求端口而非 `server.address()` 实际端口（port=0 时公告为 0）。修复：以实际端口公告。
3. **API 无 CORS**：浏览器访客节点无法直接调用。修复：`/api/*` 带 CORS 头并支持 OPTIONS 预检。
4. **测试工具自纠错**：验证套件自写的 PNG 解码器把 Up 滤波重建方向写反（减法应为加法），被端到端像素抽查抓出——应用无错，验证工具自身修正。
5. **中文 Windows 探测失效**：空闲探测的 PowerShell/C# 含中文注释，文件无 BOM 时被 PowerShell 5.1 按 GBK 解码，中文注释字节吞掉代码导致 C# 编译失败、探测静默失效。修复：ps1 带 UTF-8 BOM 写入 + C# 保持纯 ASCII。
6. **Blender 任务缺 type 标记**：提交接口生成的帧任务漏掉 `type: 'exec'`，工作节点误走 Mandelbrot 分支、协调器按定长 RGBA 校验永不通过。由提交契约测试抓出。
7. **Blender 任务缺资产清单**：帧任务没带 `assets` 字段，真 Blender 会拿到未解析的占位符路径（fake 工具忽略该参数所以 e2e 侥幸通过——契约测试兜住了 fake 测不出的错）。
8. **测试端口僵尸级联**：固定测试端口被上次运行的残留进程占住时，新协调器绑定失败秒退、测试轮询打到僵尸旧状态，表现为莫名超时。修复：测试端口按 PID 派生 + 运行后清理进程。
9. **工作节点注册无容错**：任务循环的每个请求都有重试，唯独注册这一步裸奔——协调器尚未就绪时连接被拒/挂起会让节点静默死亡（日志停在"协调器: http://..."后再无输出），且只在系统繁忙时偶发。由 SEA 测试的诊断输出（最后状态 workers 为空 + worker 输出尾部）定位。修复：注册带重试与 3 秒超时。
10. **Blender 5.x 忽略 -o 参数**：`-o <路径>####` 在 Blender 5.2 中被整体忽略，渲染结果落到其默认临时目录 `C:\tmp\0001.png`（exit=0 但预期位置无文件）。修复：渲染改走 `--python-expr`，直接把 `render.filepath` 设为精确目标路径后 `render.render(write_still=True)`，跨版本可靠。
11. **失败重试无上限（曾导致宿主机卡死）**：确定性故障（如 bug 10）会让节点陷入"渲染→判失败→重排→再渲染"的死循环，持续满负荷空转。修复三重保险：节点连续失败 5 次自动停机（熔断）；连续失败指数退避（1s→10s）；协调器侧同一任务被上报失败 5 次即标记"失败"不再重排（毒丸），仪表盘以红色"失败"块显示。

## 路线图

1. **GPU 工作节点**：Rust + wgpu 原生节点（wgpu 即 WebGPU 的原生实现），同一套协调器协议混跑。
2. **冗余校验**：确定性任务（哈希/整数类）N=2 双机比对；容错类任务（渲染/评测）单份直收。
3. **更多负载**：本地 LLM 实测天梯（夜间网格跑基准）、视频批量转码、讲义 OCR（命令行任务模板化后均可复用）。
4. **浏览器访客节点**：打开网页即可临时贡献算力（WebGPU/WASM），与原生节点共用协议。

## 为什么先用 Node 而不是 Go/Rust

本机没有 Go 工具链，为不动系统环境，MVP 用零依赖 Node 实现；协议设计与语言无关，
后续 GPU 阶段本来就要引入 Rust/wgpu 原生节点，协调器协议保持不变，两种节点可混编。
